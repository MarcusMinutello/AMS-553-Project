# AMS-553-Project

Large-field Daily Fantasy Sports (DFS) simulation: correlated player outcomes, a simulated opponent field, and lineups chosen by Upside CVaR (U-CVaR). The approach builds on Haugh & Singal (2019), *How to Play Fantasy Sports Strategically (and Win)*. See [docs/](docs/) for the paper and our proposal, and [docs/ROADMAP.md](docs/ROADMAP.md) for the plan.

## Quick start

```bash
pip install -r requirements.txt
python run_all.py --quick   # smoke test, under a minute
python run_all.py           # full run, about 2 minutes -> results/
python make_figures.py      # presentation figures -> results/figures/
```

No commercial solver is needed. Lineup MILPs use `scipy.optimize.milp` (HiGHS).

## Pipeline

| Stage | Module | What it does |
|---|---|---|
| Inputs | [src/dfs/slate.py](src/dfs/slate.py) | Synthetic 8-team, 80-player DraftKings-style slate; position-pair correlation matrix (PSD-repaired) |
| Player outcomes | [src/dfs/outcomes.py](src/dfs/outcomes.py) | Gaussian copula with lognormal marginals; optional mean-shift importance sampling with likelihood-ratio weights |
| Opponent field | [src/dfs/field.py](src/dfs/field.py) | Paper's Algorithm 1: Dirichlet-multinomial ownership, QB–WR stacking with prob. *q*, accept/reject on salary. Plus 20% optimizer-built "sharks" |
| Lineups | [src/dfs/optimize.py](src/dfs/optimize.py) | MILP lineup template; candidate pool; U-CVaR selection |
| Contests | [src/dfs/contest.py](src/dfs/contest.py) | Top-heavy payout table, ranking with tie-splitting, out-of-sample contests with splitting (10 outcome draws per field) |
| Output analysis | [src/dfs/stats.py](src/dfs/stats.py) | ROI and finish-rate CIs clustered by field; paired tests (common random numbers) |
| Variance reduction | [src/dfs/importance.py](src/dfs/importance.py) | Crude MC vs. importance sampling for P(lineup score > top-0.1% cutoff) |

All defaults live in [src/dfs/config.py](src/dfs/config.py). Each stage (candidate generation, selection, test, importance sampling) has its own seed, so selection and evaluation never share random numbers.

## Outputs (`results/`)

| File | Contents |
|---|---|
| `summary.csv` | Per strategy: ROI, P(cash), P(top 1%), P(top 0.1%) with 95% CIs |
| `paired_tests.csv` | Each strategy vs. max projection: payout difference, bootstrap CI, t-test |
| `strategies.csv` | The lineups each strategy chose |
| `pool_selection.csv` | Every candidate's in-sample metrics and out-of-sample results |
| `alpha_sensitivity.csv` | Which candidate U-CVaR picks at α = 0.90 / 0.95 / 0.99 / 0.995 |
| `is_*.csv` | Importance-sampling results (tilt choice, relative error vs. n, threshold sweep) |
| `contests.csv` | Raw per-contest results (`field_baseline.csv`, the held-out field lineups, is regenerated by `run_all.py` and not committed) |
